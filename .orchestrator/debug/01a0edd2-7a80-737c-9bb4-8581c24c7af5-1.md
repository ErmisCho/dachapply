### Suspect commits

- None. `git log --oneline -20 -- backend/config backend/manage.py` and `git diff HEAD~5..HEAD -- backend/config backend/manage.py` show no relevant regression. The failing runner is an untracked operator script outside Git.

### Instrumentation data

- `uv run python -c ...` from `backend/`: cwd is the backend directory, `sys.path[0]` is empty (current directory), and `find_spec('config')` resolves `backend/config/__init__.py`.
- Running an absolute script under `%LOCALAPPDATA%`: cwd remains the backend directory, but `sys.path[0]` becomes the script directory and `find_spec('config')` returns `None`.
- The repository is not installed as a package, so no later `sys.path` entry supplies `config`.

### Hypothesized root cause

Launching an external script by absolute path replaces Python's import root with that script's directory, leaving the repository's `backend/config` package unreachable. · Confidence: high

## Phase 2 — Pattern

This is standard Python script-path import behavior, not a recurring application defect. Repository Django entry points (`backend/manage.py`, `backend/config/wsgi.py`) live beside or beneath the import root and therefore resolve `config`. No production test is missing because production code is unaffected.

## Phase 3 — Impact

Affected file: `%LOCALAPPDATA%/dachapply/TASK-229-AC4/run_compare.py` only. Repository code, tests, management commands, and the application runtime are unaffected. Any future external operator script launched the same way needs the backend directory on `PYTHONPATH` or `sys.path`.

## Phase 4 — Solution

Run the external script with `PYTHONPATH=.` from `backend/`. This is the smallest fix and changes no repository or application code. Verify by rerunning the exact command and reaching Django setup/generation rather than `ModuleNotFoundError`.

## Resolution

Verified by rerunning with `PYTHONPATH=.`: Django setup completed and CV generation reached the provider call. No production code change or test was warranted.
