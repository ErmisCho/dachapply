### Suspect commits
- No committed change introduced these failures. All four arose in TASK-255's uncommitted integration diff.
- `backend/jobradar/views.py` expanded an established exact response contract even though no new caller needs the extra fields.

- `frontend/src/App.tsx` moved source editing into shared `PostingSource`; two raw-source assertions still name the former textarea/disabled-expression shape.

## Phase 2 — Pattern

This is boundary-contract drift during consolidation: persistence behavior is correct, but API response shape, test doubles, raw-source UI tests, and save affordances were not updated as one unit. Search shows `generation_preview` has multiple direct non-model callers, while `PostingSource` is shared by single and batch generation. Existing tests caught the API/test-double and source-shape changes; a focused save-path assertion should pin the missing action.

## Phase 3 — Impact

Affected production files: `backend/jobradar/views.py`, `backend/jobradar/services/cv_generator.py`, `frontend/src/App.tsx`. Affected tests: `frontend/src/cvPopup.test.tsx`; existing backend API tests should remain unchanged to preserve compatibility. `frontend/src/postingSource.test.tsx` already verifies staged comparison controls. Batch accepted text should be read-only when no staged candidate exists unless a real persistence action is added.

## Phase 4 — Solution

Keep the existing PATCH response shape while still atomically clearing pending state. Read new preview fields via `getattr(..., safe_default)` for job-shaped callers. Restore one single-generator save button when no pending candidate exists, keep generation gated by unsaved state and pending review, and make batch accepted text editable only during an explicit pending comparison. Update raw-source tests to assert behavior and the new shared accessible label rather than exact token adjacency. Remove temporary test logs and trailing whitespace, then run focused and full gates.
