# Debug session: TASK-221 quality-review regressions
Created: 2026-09-13T12:00:00Z

## Phase 1 — Root Cause

### Error

Read-only quality review found four reproducible defects before merge:

```text
1. OLLAMA_HOST=https://remote.example sends candidate evidence and CV TeX outside localhost.
2. draft_chat.py still routes offered Ollama models through codex --oss --local-provider ollama, which fails with: failed to decode models response: missing field 'models'.
3. If initial structured output is invalid before TeX is written, the compact repair prompt loses candidate evidence, job description, adaptation rules, and the original instruction.
4. Cancelling a local HTTP call raises GenerationCancelled in the caller while the daemon HTTP thread and local inference continue.
```

No command exited non-zero; these are pre-merge review failures.

### Reproduction

- Set `OLLAMA_HOST=https://remote.example` and inspect the URL built at `cv_generator.py` local-provider dispatch.
- Call `draft_chat.run_chat_turn` with an Ollama option and observe its unchanged Codex local-provider command.
- Make initial `run_structured_model` output invalid before `generate()` writes TeX, then inspect attempt two's prompt.
- Stub `urlopen` with a blocking response, set cancellation after the request starts, and observe the worker remains alive.

Environment: current uncommitted TASK-221 branch on Windows; findings derived from the complete diff and every `run_structured_model`/model-picker caller.

Frequency: deterministic from the named inputs.

### Suspect commits

- Current TASK-221 local-provider diff: direct HTTP added flexible `OLLAMA_HOST`, changed shared discovery, compacted every repair, and used a daemon thread without closing its response.

### Instrumentation data

- Local requests carry the complete candidate/job prompt and current TeX.
- `available_model_options` is shared by CV generation, evaluation, and draft chat.
- `generate()` writes TeX only after both structured-response parsing and document-shape checks pass.
- The cancellation loop owns no reference to the open response, so it cannot close it.

### Hypothesized root cause

The first direct-local-provider pass changed a shared provider surface without preserving its localhost, caller-compatibility, pre-write retry, and cancellation invariants. · Confidence: high

## Phase 2 — Pattern

All four defects are boundary regressions: local/remote trust boundary, shared-picker caller boundary, response-validation/write boundary, and caller/thread lifecycle boundary. Focused happy-path tests missed each negative branch.

## Phase 3 — Impact

Affected production files:
- `backend/jobradar/services/cv_generator.py`
- `backend/jobradar/services/draft_chat.py` only if local draft chat is migrated; otherwise it needs an immediate compatibility refusal through shared validation.

Affected tests:
- `backend/jobradar/tests/test_local_provider.py`
- `backend/jobradar/tests/test_draft_chat.py`
- existing CV-generation tests when repair behavior is corrected.

## Phase 4 — Solution

1. Permit only HTTP loopback addresses for local-provider requests and disable environment proxies.
2. Keep scope minimal: make draft chat refuse the incompatible Ollama/Codex path immediately with a specific explanation unless it is migrated to shared HTTP in the same small diff.
3. Use compact repair only after a valid generated TeX document was written; otherwise retain the full generation context.
4. Keep a reference to the open local response and close it on cancellation; add a blocking-response test proving the worker exits rather than merely proving preflight cancellation.
