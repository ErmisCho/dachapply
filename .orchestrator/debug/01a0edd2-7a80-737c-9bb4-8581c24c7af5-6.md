# Debug session: local Azure CLI cannot read rollback image
Created: 2026-09-29T20:43:00Z
Session: 01a0edd2-7a80-737c-9bb4-8581c24c7af5

## Phase 1 — Root Cause

### Error

```text
ERROR: AADSTS530035: Access has been blocked by security defaults.
Run the command below to authenticate interactively; additional arguments may be added as needed:
az logout
az login --tenant "18fd9fda-94d4-41e9-9e36-326ec5a5876f" --scope "https://management.core.windows.net//.default"
```

The container-app query returned no image or revision.

### Reproduction

```bash
az containerapp list --query "[?name=='dachapply'].resourceGroup | [0]" -o tsv
```

Environment: Windows Azure CLI with cached account metadata; frequency: 3/3 management API calls in the rollback-image query.

### Suspect commits

- None. Authentication fails before repository or application state is read.

### Instrumentation data

- `az account show` can read cached subscription metadata.
- Every Azure Resource Manager call is rejected with the same AAD security-defaults code.
- The error explicitly requires interactive tenant authentication; retrying the same token cannot change the outcome.

### Hypothesized root cause

The local Azure CLI cache has account metadata but no currently accepted Resource Manager token under the tenant's security-defaults policy. · Confidence: high

## Phase 2 — Pattern

This is external operator authentication expiry/policy enforcement, not a container-app or repository failure. CI deploys with separate `AZURE_CREDENTIALS`, so local interactive auth and deployment auth are independent.

## Phase 3 — Impact

The local session cannot query the currently active Azure image directly. PR checks, GitHub Actions deployment, public health, and local runtime are unaffected.

## Phase 4 — Solution

Do not trigger an unsolicited interactive login. Derive the rollback image from the latest successful `main` deployment: the workflow deterministically tags every deployed image as `ghcr.io/ermischo/dachapply:<github.sha>`, and a successful run proves that exact SHA was updated and its public verification passed. Record the run ID and SHA before merge.

## Resolution

Recorded rollback image `ghcr.io/ermischo/dachapply:6e24c399759d786dce0809e1053265ccadecedfe` from successful main deployment run 36453037961, which completed its public-app verification on 2026-09-28. No production code changed.
