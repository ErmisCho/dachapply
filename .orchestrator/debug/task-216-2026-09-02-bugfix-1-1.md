# Debug session: CV generator popup grows after preview discovery
Created: 2026-09-02T16:03:33+02:00
Session: task-216-2026-09-02-bugfix-1

## Phase 1 — Root Cause

### Error
`works but now make it that the button generate CV and Motivation Letter opens fully smoothly instead of halff opening instantly and then waiting for 6 seconds for hte full window to open`

No exception or stack trace is raised; the defect is visible layout shift.

### Reproduction
Open `http://localhost:5173/` in Chrome as the synthetic demo account, enable the existing CV control only in browser-local state, intercept `/api/jobs/<id>/cv-generation/` with a synthetic response delayed by 6000 ms, select one synthetic job, click `Generate CV and Motivation Letter`, and sample the popup bounding box before and after the response.

Environment: Windows, Chrome via CDP 9222, Node v26.3.1, Vite development frontend on port 5173, origin/main `cd5695b`.
Frequency: always (1/1 delayed response run).

### Suspect commits
- `59376b7 feat: add local AI CV generation workflow` — introduced `CvGenerator` and its async preview dependency.
- `a2e4a5e fix(cv): use the newest base CV template, show full paths, cache model discovery` — introduced the compact popup's current `max-h-[80vh]` shell without reserving that height.

### Instrumentation data
- 286 ms after click: popup `(x=224.32, y=1954.76, width=704, height=81.28)`; only heading/help text rendered; no Close button.
- 4281 ms after click: identical `(x=224.32, y=1954.76, width=704, height=81.28)`.
- 8275 ms after click, after the synthetic preview resolved: `(x=224.32, y=1954.76, width=704, height=1028.60)` with complete controls and Close button.
- Measured layout shift: `+947.32 px` height; x, y, and width stayed unchanged.
- Data-flow trace: Dashboard selection mounts compact `CvGenerator` immediately → `preview` starts as `null` → the entire controls grid and its Close button are guarded by `{preview && ...}` → async `/cv-generation/` resolves → the controls grid mounts → `max-height` caps overflow but does not reserve height, so the popup grows from content height to 80vh.

### Hypothesized root cause
The compact popup uses only `max-height` while conditionally omitting its complete controls until preview discovery resolves, so its intrinsic height grows by the full controls height when async data arrives. · Confidence: high

## Phase 2 — Pattern

This is an async intrinsic-size layout shift: `max-height` limits an oversized element but reserves no space for content that has not mounted yet. The existing batch generator already renders an explicit `Loading` state, but its separate full-screen modal is not a caller of this compact popup. No other `CvGenerator` caller uses compact mode.

A regression test should render the compact component before effects resolve and assert that the shell already carries a fixed viewport height, dialog semantics, an immediate loading status, and a Close button.

## Phase 3 — Impact

Affected production file: `frontend/src/App.tsx`.

Callers checked:
- Dashboard's one-selected-job action mounts `<CvGenerator compact ...>` and exhibits the defect.
- Job Detail mounts `<CvGenerator job={j}/>` without compact mode; its normal in-page section must retain intrinsic height.
- `BatchCvGenerator` is a separate component and is not changed.

The fix must not change preview fetching, provider/model defaults, generation requests, or task polling. It only needs to stabilize the compact shell and expose loading/close semantics while the existing request runs.

## Phase 4 — Solution

Give only the compact shell a fixed `80vh` border-box height (the same existing viewport cap), keep overflow scrolling, render an immediate loading status while `preview` is absent, move its Close button outside the preview guard, and apply the app's existing `useDismiss` focus/Escape policy. Add one server-rendered frontend regression for the initial shell, then measure the delayed transition again in Chrome and run the frontend suite/build plus the configured backend suite.

## Resolution

Implemented in commit `95d28bd`: `frontend/src/App.tsx` now gives only the compact generator a fixed 80vh shell, immediate loading/Close controls, and the existing focus/Escape policy; `frontend/src/cvPopup.test.tsx` guards the initial shell. Synthetic Chrome measurement changed from +947.32px height shift to 0px, the popup mounted in 38.3ms, 207 frontend tests and the production build passed, and 1054 backend tests passed.
