# TASK-209 second demo-login verifier did not reach Dashboard

## Symptom

After reload had intentionally exposed the insecure-localhost session limit, a second `Try demo` click did not return to Dashboard within the verifier's 90-second bounded poll.

## Investigation

The verifier confirmed it found/clicked the button. Next inspect the visible login error and request state. Do not alter app auth settings or owner data to make a TASK-209 UI check pass.

## Root cause

The second synthetic demo transition eventually reached `/` with the full demo board and no alert, but after the verifier's 90-second poll. This production-configured localhost proxy/remote-database setup has an unusually slow dashboard settle; authentication did not fail.

## Resolution

The eventually loaded Dashboard is reused for the persisted-state observation without another fixed readiness assumption. The normal deployed HTTPS reload check remains the authoritative persistence verification after merge.
