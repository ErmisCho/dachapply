# Debug session: reloaded test URLconf omits DEBUG-only redirect
Created: 2026-08-30T14:15:30Z
Session: task-205-2026-08-30-bugfix-1

## Phase 1 — Root Cause

### Error

Exact second focused-test failure after isolating URL resolution:

```text
response = resolve('/', urlconf=config.urls).func(request)
django.urls.exceptions.Resolver404: {'tried': [[<URLPattern 'admin'>], [<URLResolver ... 'admin/'>], [<URLResolver ... 'api/'>]], 'path': ''}
1 failed, 4 passed in 0.46s
```

Command exit code: 1.

### Reproduction

```bash
cd backend
uv run pytest -q jobradar/tests/test_settings.py::test_local_root_redirects_to_vite_when_frontend_build_is_missing
```

Environment: Windows, CPython 3.13.5, pytest-django test environment. Frequency: always.

### Suspect commits

- Current uncommitted regression test — it overrides the dist path and frontend URL but assumes test-time `settings.DEBUG` is true.
- No production commit is implicated.

### Instrumentation data

Temporary pre-resolution instrumentation printed:

```text
debug-urlpatterns False False http://localhost:5173 ['admin', 'admin/', 'api/']
```

This proves:

- `FRONTEND_DIST.exists()` is false as intended.
- `FRONTEND_URL` is set as intended.
- pytest-django’s test environment has `settings.DEBUG=False`, despite `config.settings_test` defaulting the environment variable before importing base settings.
- Reloading `config.urls` therefore correctly omits both the new DEBUG-only root redirect and DEBUG static patterns.
- A standalone `DJANGO_SETTINGS_MODULE=config.settings_test` script outside pytest reports `DEBUG=True`, installs the empty route, and resolves `/` to `RedirectView`; the difference is pytest-django’s test-environment override.

### Hypothesized root cause

The regression test did not explicitly enable the DEBUG condition it was designed to exercise, and pytest-django sets runtime `settings.DEBUG` to false. · Confidence: high

## Phase 2 — Pattern

This is a test precondition omission. Environment defaults are not stable once a framework’s test harness mutates settings; branch tests must set every branch-defining setting explicitly and restore module state afterward.

## Phase 3 — Impact

Affected only: the focused test setup/cleanup in `backend/jobradar/tests/test_settings.py`. Production URL behavior is correct under the measured runtime’s `DEBUG=True`. The test must restore DEBUG along with FRONTEND_DIST and FRONTEND_URL to avoid cross-test leakage.

## Phase 4 — Solution

Save the original DEBUG value, set `settings.DEBUG=True` before reloading `config.urls`, remove temporary instrumentation, and restore DEBUG with the other settings before the final reload.

## Resolution

The test now explicitly saves, enables, and restores `settings.DEBUG` along with the other branch settings before each URLconf reload. Removed temporary instrumentation. The focused pair passed 5 tests in 0.30s and the full backend suite passed 1028 tests.
