## Phase 4 — Solution

- Change only the stale-row branch from `text-slate-500` to `text-slate-600` (6.9170:1 light; 11.9870:1 dark).
- Add `main > .field-error-message{color:#dc0021}` so only a bare page-level error changes (4.7783:1 on the measured `#f3f6fe`; at least 4.6199:1 across the page gradient endpoints); leave the shared nested-error colour unchanged.
- Extend `darkSurfaces.test.tsx` with exact source guards and WCAG contrast calculations for the changed pairs plus the unchanged nested-error surfaces.
- Prove each guard by temporarily reverting one fix at a time and observing a targeted failure, then restore and run the frontend tests/build and backend suite.

## Implementation test finding

The first targeted run failed at `darkSurfaces.test.tsx:94` with `expected 3 to be 2`: the old guard counted every `.field-error-message{` selector to prevent popup-specific overrides, so the new single page-level selector correctly became its third match. This is not a production regression; the assertion's count encoded the previous two-selector design. Keep the intent by expecting exactly the base, page-level, and dark selectors, while the new exact selector assertion prevents the page rule from widening to cards/windows.

## Resolution

Changed `frontend/src/App.tsx`, `frontend/src/index.css`, and `frontend/src/darkSurfaces.test.tsx`. Browser-computed styles matched the intended scoped values; measured contrast is 6.9170:1 for the stale row and 4.7783:1 for the bare ErrorBox on the reported page pixel. Independent reverts made the regression guard fail for each fix. Verification passed: 6/6 targeted tests, 297/297 frontend tests, frontend production build, and 1225/1225 backend tests.
