### Hypothesized root cause
The test compares the UTC storage date of `sent_at` with a deliberately local-calendar-date audit note. · Confidence: high

## Phase 2 — Pattern

This is a timezone-boundary assertion bug: aware timestamps are stored in UTC, while user-facing calendar dates use the configured timezone. Search found this one assertion on `sent_at.date()` in the follow-up confirmation tests.

## Phase 3 — Impact

Affected file: `backend/jobradar/tests/test_api.py`. Production behavior and data are correct and must not change. The failure can recur every day when UTC and Europe/Vienna are on different calendar dates.

## Phase 4 — Solution

Convert `sent_at` with Django's `timezone.localtime()` before taking `.date()` in the existing assertion. Rerun the focused test at the live boundary and the full GitHub Actions workflow.

## Resolution

Changed the existing assertion to use `timezone.localtime(followup.sent_at).date()` while UTC and Europe/Vienna were on different calendar dates. The focused regression passed (`1 passed`); full verification runs in GitHub Actions.
