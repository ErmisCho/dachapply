### Suspect commits

- Current uncommitted `cv_generator.py` change enables strict JSON and inline source; it exposed the next validation layer but did not introduce the malformed TeX produced by the model.
- Prior TASK-221 runs through Codex failed earlier on malformed JSON and never reached compilation, so TeX validity for this model had not previously been measured.

### Instrumentation data

- The first run reached `Compiling CV`, proving LM Studio returned schema-valid JSON with a structurally complete `cv_tex` field.
- The first run then entered both repair attempts and failed after 114 seconds.
- The synchronous reproduction captured a missing-brace TeX error at the same role-heading macro on attempts 1 and 2.
- Attempt 3 passed JSON grammar but failed the application's document check, proving strict response format enforces JSON shape, not TeX correctness.
- Real evaluation passed separately, isolating the failure to long application-document generation rather than provider connectivity or JSON-schema transport.

### Hypothesized root cause

The 7B Qwen model cannot reliably preserve the real CV template's TeX syntax across this long transformation even when LM Studio enforces the outer JSON schema. · Confidence: high

## Phase 2 — Pattern

This is model capability, not transport: JSON-schema enforcement prevents malformed JSON but cannot guarantee syntactically valid LaTeX inside a string. Existing `_compile_pdf` and two repair attempts correctly reject the output. No deterministic parser can infer the missing intended brace without risking document corruption.

The existing tests correctly avoid asserting that a model's advertised tool flag implies document-generation quality. A regression test for this exact model output would test a nondeterministic external model rather than application logic.

## Phase 3 — Impact

- `qwen2.5-7b-instruct` is proven suitable for job evaluation but not yet for the real CV task.
- The LM Studio provider path itself remains viable; installed `google/gemma-3-12b` is larger, has a 131,072 maximum context, and no longer needs tool training because source is inline.
- No application-code change can honestly convert the measured Qwen output into valid TeX without either a different model or a substantially different generation workflow.

## Phase 4 — Solution

Measure the stronger installed `google/gemma-3-12b` through the same unchanged provider path. If it completes both a real dry-run evaluation and CV generation, use that model as the AC4 evidence; do not add model-specific repair code. If it also fails, stop and re-scope rather than masking model output defects.
