# Debug session: TASK-207 detached Vite process exited with launcher
Created: 2026-08-31T13:58:00Z
Session: task-207-2026-08-31-bugfix-3

## Phase 1 — Root Cause

### Error

The PowerShell launch printed `pid=71864` but the tool exited with code `4294967295`; moments later port 5173 had no listener. Vite's log shows it reached `ready in 303 ms` before disappearing.

### Reproduction

Start `cmd /c npm run dev` through PowerShell `Start-Process` from the tool shell and then test port 5173 after PowerShell exits. Frequency: 1/1.

### Suspect commits

None; local verification process lifetime only.

### Instrumentation data

- Vite stdout proves successful startup.
- A subsequent `curl` reports connection refused and `netstat` shows no listener.
- No Vite error was written.
- Therefore startup is healthy; process lifetime is coupled to the launcher/tool job rather than product failure.

### Hypothesized root cause

The nested hidden `Start-Process cmd /c` launch did not survive its tool/PowerShell job lifetime, so the healthy Vite child exited when the launcher ended. · Confidence: medium

## Phase 2 — Pattern

Detached-process behavior differs under the coding harness on Windows. A one-command start/test/stop lifetime is deterministic and needs no detachment.

## Phase 3 — Impact

No product or data state changed. Released Vite remains stopped pending restoration after branch verification.

## Phase 4 — Solution

Start Vite in the background inside one Bash invocation, poll the branch harness marker, run the CDP interaction before that shell exits, and terminate the known child in a trap.

## Resolution

Ran Vite, the CDP interaction, and cleanup in one shell lifetime. Browser checks proved all six initial labels/actions, populated edit state, Save availability, both AI modes, exact-draft wording, and the default revise selection.
