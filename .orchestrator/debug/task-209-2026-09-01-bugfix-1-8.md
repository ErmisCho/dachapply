# TASK-209 toggle persistence verifier reload timeout

## Symptom

The real-dashboard interaction reached the reload step, then timed out after 30 seconds waiting for `Feedback deadlines` to reappear.

## Investigation

The script had already read the live control and clicked Hide upcoming before reload. The next step is to inspect URL, authentication state, visible body, storage, and Vite logs before changing code or retrying.

## Root cause

Reload returned to `/login` while local storage retained `dachapply_feedback_due_show_upcoming=false`. Cookie inspection showed no `sessionid` (only non-secure CSRF/visitor cookies): this production-configured backend's demo login can drive the current HTTP SPA transition, but the session cookie is not retained for an insecure localhost reload. API health and Vite both remained HTTP 200.

## Resolution

Verify persisted initialization by logging into the synthetic demo again after reload: this remounts the real Dashboard while preserving local storage. Production persistence will be rechecked over the deployed HTTPS origin after merge. No auth/cookie product setting is changed for TASK-209.
