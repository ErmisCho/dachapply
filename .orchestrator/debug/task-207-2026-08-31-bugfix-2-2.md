# Debug session: TASK-207 browser harness reached released runtime instead of branch
Created: 2026-08-31T13:54:00Z
Session: task-207-2026-08-31-bugfix-2

## Phase 1 — Root Cause

### Error

```text
TimeoutError: Waiting failed: 30000ms exceeded
```

The synthetic page showed only the normal app theme button; `Draft or rewrite` never appeared.

### Reproduction

Open `http://localhost:5173/task207-harness.html`, click the expected synthetic draft AI button, and wait for its mode labels.
Environment: Node v26.3.1 / Chrome CDP 9222. Frequency: 1/1.

### Suspect commits

None. This is local verification process state.

### Instrumentation data

- `curl /task207-harness.html` returned the normal production `index.html` with `/src/main.tsx`, not the temporary harness.
- The branch Vite stderr says `Error: Port 5173 is already in use`.
- `wmic` identifies PID 236888 as the released main-runtime Vite process and PID 219508 as the released main-runtime Django process.
- The earlier stop command printed an interactive `cmd.exe` prompt and did not stop either listener; the subsequent HTTP-200 readiness check therefore measured the old listeners, not the branch processes.

### Hypothesized root cause

The Windows stop script was invoked through an MSYS-ambiguous `cmd /c` form that did not execute, so readiness checks falsely passed against the already-running released runtime. · Confidence: high

## Phase 2 — Pattern

Port-ready is not revision-ready. A listener check must also verify the listener's process command line or use isolated ports.

## Phase 3 — Impact

No product, database, or Gmail data changed. The browser interacted only with the normal localhost app and timed out before any control action.

## Phase 4 — Solution

Terminate only the two verified main-runtime listener PIDs, start the branch processes on the expected ports, verify command lines and the harness HTML marker, then rerun the synthetic browser interaction. Restore the released runtime afterward.

## Resolution

Verified the listener PIDs, stopped only released Vite, and served the branch harness in a bounded start/test/stop command. The released runtime was restored afterward at SHA `6a17c8a` with API/web HTTP 200.
