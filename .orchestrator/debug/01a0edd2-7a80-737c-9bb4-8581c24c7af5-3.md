# Debug session: private comparison judge schema rejected
Created: 2026-09-29T16:00:00Z
Session: 01a0edd2-7a80-737c-9bb4-8581c24c7af5

## Phase 1 — Root Cause

### Error

Both independent judge commands exited 1 before reading the private CVs:

```text
ERROR: {
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "code": "invalid_json_schema",
    "message": "Invalid schema for response_format 'codex_output_schema': In context=('properties', 'factual_disagreement_categories'), 'uniqueItems' is not permitted.",
    "param": "text.format.schema"
  },
  "status": 400
}
```

### Reproduction

```bash
codex exec --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check \
  --sandbox read-only --model <model> --cd "$LOCALAPPDATA/dachapply/TASK-229-AC4" \
  --output-schema judge-schema.json --output-last-message judge-<model>.json - < judge-prompt.txt
```

Environment: Windows; Codex CLI 0.146.0; reproduced 2/2 with `gpt-5.6-sol` and `gpt-5.6-terra`.

### Suspect commits

- None. `judge-schema.json` is a new private operator artifact outside Git. The provider rejected it at request validation.

### Instrumentation data

- Both stderr files identify the same schema property and keyword.
- Both stdout files are empty and neither output-last-message file exists, confirming no CV review ran.
- A prior schema without `uniqueItems` passed the same CLI/provider boundary.

### Hypothesized root cause

The provider's structured-output JSON Schema subset does not permit `uniqueItems`, which the private judge schema used on its category array. · Confidence: high

## Phase 2 — Pattern

This is a structured-output compatibility restriction. Repository schemas already use the supported minimal subset and contain no `uniqueItems` usage in this path.

## Phase 3 — Impact

Only `%LOCALAPPDATA%/dachapply/TASK-229-AC4/judge-schema.json` is affected. No model reviewed private data, no generated artifact changed, and production code is unaffected.

## Phase 4 — Solution

Remove `uniqueItems` from the private schema. Duplicate enum categories are harmless to the pass/fail decision; the counts and assessment remain constrained. Rerun both judges and require valid output from each.

## Resolution

Removed the unsupported keyword from the private schema. Both independent judge runs then completed with valid structured output. No production code change was needed.
