### Suspect commits

- `16ecb35 feat(cv): self-healing generation, package cache, and no-stall compilation` — introduced the copy control's dependency on in-memory task metadata.

### Instrumentation data

- The targeted backend tests pass (`2 passed`), confirming `latest_generated_artifacts()` rediscovers generated files after in-memory task state is gone.
- `generation_preview()` returns those files under `artifacts` but returns no `clipboard_tex`.
- On a freshly opened popup, frontend `task` is `null`; the copy control is disabled by `!task?.clipboard_tex`, even while `preview.artifacts` renders the four existing files.
- `generate()` posts immediately to `/jobs/<id>/cv-generation/run/`; it never examines `preview.artifacts`, so no confirmation can occur before a replacement attempt.
- `frontend/src/api/client.ts` lets a rejected native `fetch()` surface as the exact browser message `Failed to fetch`; the user confirmed the backend server was stopped.
- The generated files remain on disk independently of server availability and in-memory task state.

### Hypothesized root cause

The request failed because the backend server was stopped, while the separate disabled Copy TeX control relied on ephemeral task state instead of persisted preview artifacts. · Confidence: high

## Phase 2 — Pattern

This is the same lifecycle split behind restart-safe artifact display: task records are memory-only, while generated files persist on disk. The frontend already has a shared `copyToClipboard()` fallback, but this control bypasses it with direct `navigator.clipboard` access. A focused frontend predicate/wiring test and a preview-response test would have caught both regressions.

## Phase 3 — Impact

Affected files and paths:

- `backend/jobradar/views.py`: preview response boundary.
- `backend/jobradar/services/cv_tasks.py`: existing canonical TeX clipboard payload builder.
- `frontend/src/App.tsx`: single-job Generate and Copy TeX controls.
- `frontend/src/cvModel.ts`: minimal pure selection predicates for DOM-free tests.
- `frontend/src/cvSelection.test.ts`: repeat-generation and clipboard-source checks.
- `backend/jobradar/tests/test_api.py`: restart-safe preview payload check.

The batch generator also consumes preview artifacts, but the reported disabled control is the single-job popup; no batch behavior needs to change for this fix.

## Phase 4 — Solution

- Add the canonical existing-file clipboard payload to the owner-only generation preview.
- Before a single-job generation request, use native `window.confirm` when any selected output already exists; cancellation returns before mutating UI state or sending a request.
- Let Copy TeX use completed-task content when available and persisted preview content after reopen, through the existing `copyToClipboard()` helper.
- Add focused backend and DOM-free frontend tests for the preview payload, selection-aware confirmation predicate, and task/preview clipboard fallback.
