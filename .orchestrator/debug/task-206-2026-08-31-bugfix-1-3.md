# Debug session: branch-code production read used empty SQLite database
Created: 2026-08-31T08:31:00Z
Session: task-206-2026-08-31-bugfix-1

## Phase 1 — Root Cause

### Error

The read-only branch-code verification failed at its first lookup:

```text
sqlite3.OperationalError: no such table: jobradar_mailboxdraft
...
django.db.utils.OperationalError: no such table: jobradar_mailboxdraft
```

Command exit code: 1.

### Reproduction

Attempt to create an ignored temporary hard link to the repository `.env` through a Git-Bash-expanded `cmd.exe /c mklink` command, then run the isolated worktree’s `manage.py shell` for a read-only serializer/classifier check.

Environment: Windows, isolated TASK-206 worktree, scheduler disabled, explicit production-DB opt-in. Frequency: observed once.

### Suspect commits

- No repository commit. The failure occurred in the one-off shell setup before branch code could query the intended database.

### Instrumentation data

- The exception came from local SQLite and said its schema table did not exist, proving the intended configured database was not loaded.
- The failed command’s EXIT trap removed the temporary `.env` path; no tracked file was changed.
- Recreating the same hard link with PowerShell `New-Item -ItemType HardLink` produced equal source/link lengths (1234 bytes).
- With that PowerShell-created link, a no-query settings inspection reported `DJANGO_SETTINGS_MODULE=config.settings`, the isolated worktree base directory, and `django.db.backends.postgresql` rather than SQLite.
- Scheduler startup remained disabled and neither diagnostic contacted Gmail.

### Hypothesized root cause

The Git-Bash-to-`cmd.exe` quoting did not leave the intended `.env` link at the worktree path, so settings fell back to an uninitialized local SQLite database. · Confidence: medium

## Phase 2 — Pattern

This is another diagnostic environment setup failure. Cross-shell Windows path quoting is unnecessary here; PowerShell has a native hard-link operation and provides a directly inspectable result.

## Phase 3 — Impact

Only the read-only verification command failed. The temporary path was removed, the local empty SQLite database is ignored, and no production row, Gmail object, tracked file, or running server was changed.

## Phase 4 — Solution

Use PowerShell’s native hard-link operation, verify settings selects PostgreSQL before querying, run the bounded read-only classifier/serializer check, and remove the temporary link afterward.

## Resolution

Created the temporary ignored link with PowerShell, asserted the worktree settings selected PostgreSQL, and ran the bounded read-only check. The branch code reports the existing draft stale because the owner already replied and now classifies the closure as `rejection`; database writes and Gmail calls were both zero. Removed the temporary `.env` link and ignored SQLite artifact afterward.
