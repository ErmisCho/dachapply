# Debug session: scoped production metadata query cannot print sender Unicode
Created: 2026-08-31T08:13:30Z
Session: task-206-2026-08-31-bugfix-1

## Phase 1 — Root Cause

### Error

The read-only, Formunauts-scoped metadata query failed while printing JSON:

```text
UnicodeEncodeError: 'charmap' codec can't encode character '\U0001f680' in position 1326: character maps to <undefined>
```

Command exit code: 1.

### Reproduction

```bash
cd C:/Users/Administrator/AppData/Local/dachapply/main-runtime/backend
DACHAPPLY_DEMO_SEED_SCHEDULER=0 DACHAPPLY_ALLOW_PROD_DB=1 uv run python manage.py shell -c '<read-only scoped query; json.dumps(..., ensure_ascii=False)>'
```

Environment: Windows console using CP1252 output, released runtime `ad4ef3f`, scheduler explicitly disabled. Frequency: always for this result because one stored sender/subject value contains U+1F680.

### Suspect commits

- No application commit. The query explicitly requested unescaped Unicode (`ensure_ascii=False`) while stdout used Windows CP1252.

### Instrumentation data

- Django loaded successfully and imported 24 objects.
- The exception arose only in `print(json.dumps(...))`; no model save/update/delete method was called.
- The query selected only Formunauts job/message/draft/suggestion metadata and did not contact Gmail.
- `DACHAPPLY_DEMO_SEED_SCHEDULER=0` prevented scheduler startup and background writes.

### Hypothesized root cause

The diagnostic serializer emitted a stored emoji directly to a CP1252 console that cannot encode it. · Confidence: high

## Phase 2 — Pattern

This is a diagnostic output-encoding mismatch, not mailbox behavior. Windows read-only scripts that print arbitrary owner metadata must force UTF-8 or retain JSON's default ASCII escaping.

## Phase 3 — Impact

Only the diagnostic command output failed. Repository files, database rows, Gmail, drafts, and the running application were unchanged.

## Phase 4 — Solution

Rerun the same read-only scoped query with `PYTHONIOENCODING=utf-8` (or default JSON escaping), keeping the scheduler disabled and making no writes.

## Resolution

Reran the identical read-only, job-scoped query with `PYTHONIOENCODING=utf-8`; it completed successfully. No write method or Gmail transport was called. The metadata established the chronology used by the primary TASK-206 root-cause artifact without persisting message bodies or personal content in the repository.
