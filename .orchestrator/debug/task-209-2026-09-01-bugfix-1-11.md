# TASK-209 toggle verifier expected zero rows incorrectly

## Symptom

The live toggle verifier measured `Show upcoming`, `aria-pressed=false`, storage `false`, and 1 row after remount; it exited 1 because it had asserted hidden upcoming means 0 total rows.

## Root cause

The task explicitly requires the upcoming button to leave overdue visibility unchanged. The demo fixture has one overdue row, so hiding only today/upcoming correctly retained 1 row. Restoring upcoming produced 5 rows while the overdue checkbox remained checked in both states. The verifier's zero-row assumption contradicted the acceptance criterion.

## Resolution

The corrected interaction passed: shown = 5 rows / pressed true / stored true; hidden = 1 overdue row / pressed false / stored false; restored = 5 rows / pressed true / stored true. The overdue checkbox remained true throughout, and the prior Dashboard remount had already initialized from stored false with the same one overdue row. No product code change was needed.
