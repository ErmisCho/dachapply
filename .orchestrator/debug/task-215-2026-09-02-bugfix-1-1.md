## Phase 2 — Pattern

This is the same routing class as TASK-214 but a deliberately unsupported input shape, not a failed one-line optimization. Both generation and compile-only paths share the strict temporary-directory cleanup pattern. Missing regressions: multiline exact blocks, bounded wildcard uniqueness, already-applied blocks, ambiguous wildcard fallback, and cleanup-lock tolerance.

## Phase 3 — Impact

Affected files:
- `backend/jobradar/services/cv_generator.py`: exact parser/matcher and both temp contexts.
- `backend/jobradar/tests/test_api.py`: parser, route, real supplied-request, and cleanup regressions.
- Correction images and ambiguous/unbounded blocks must continue through AI.
- Owner scoping remains in `revise_latest_cv_documents` before parser access.

## Phase 4 — Solution

Parse multiline OLD/NEW blocks up to explicit section boundaries, support a line containing only `...` as a bounded non-greedy wildcard, require exactly one source match, and recognize an exact NEW block as already applied. Use `TemporaryDirectory(ignore_cleanup_errors=True)` for disposable model/compile workspaces so a late Windows cleanup lock cannot overturn successful persistence. Keep ambiguous inputs on AI fallback.

## Resolution

Generalized exact parsing to multiline OLD/NEW and `Replace ... from:`/`with:` blocks, with one bounded line-only ellipsis and unique-match enforcement. Both disposable workspaces now tolerate cleanup-only locks through the standard-library `ignore_cleanup_errors` flag; compile/generation/persistence exceptions inside the context remain unchanged. The exact supplied Salesforce prompt measured 0.67 ms in the parser, returned already-applied with 0 model/compiler calls, and its existing PDF remains 2 pages. Focused backend tests and 206 frontend tests/build passed; full gates and released API verification remain pending.
