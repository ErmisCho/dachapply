## Phase 2 — Pattern

This is a test-double contract drift class, not a production persistence failure. Existing tests mock the generator to isolate ETA/cache behavior and intentionally return only the fields those tests consume. No prior commit fixes this exact provenance case; `b3b205b` concerns import provenance. The new focused tests correctly exercise real provenance separately.

## Phase 3 — Impact

Affected:
- `backend/jobradar/services/cv_tasks.py` — persistence should run only when the generator actually returned the provenance contract key.
- `backend/jobradar/tests/test_api.py` — the direct revision equality test must pass the prior package's lineage, matching production task behavior.

Unaffected:
- Fresh generation and cache metadata already contain provenance.
- Failed/cancelled production generations still do not reach the persistence boundary.
- Report aggregation and job linkage are independent of these legacy test doubles.

## Phase 4 — Solution

Minimal fix:
1. In `_run()`, call `_record_base_templates` only when `'base_templates' in artifacts`; every real post-TASK-192 generator result has the key, while old/specialized mocks do not.
2. Pass `saved['base_templates']` into the direct revision calls in `test_cv_generation_uses_temporary_copies`, matching the production revision contract.
3. Re-run the three reproductions, focused provenance tests, then the full backend suite.
