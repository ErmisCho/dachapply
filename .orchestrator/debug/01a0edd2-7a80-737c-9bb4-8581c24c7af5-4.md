# Debug session: frontend build cannot find TypeScript in clean worktree
Created: 2026-09-29T16:20:00Z
Session: 01a0edd2-7a80-737c-9bb4-8581c24c7af5

## Phase 1 — Root Cause

### Error

```text
> build
> tsc && vite build

'tsc' is not recognized as an internal or external command,
operable program or batch file.
```

Exit code: 1.

### Reproduction

```bash
cd .claude/worktrees/task-229-ac4/frontend
npm run build
```

Environment: Windows; Node v26.3.1; npm 11.17.0; frequency: always in this clean worktree.

### Suspect commits

- None. Recent history for `frontend/package.json` / lockfiles contains no dependency regression, and this task changes no frontend source or package metadata.

### Instrumentation data

- `.claude/worktrees/task-229-ac4/frontend/node_modules`: missing.
- Owner checkout `frontend/node_modules`: exists.
- Owner checkout `frontend/node_modules/.bin/tsc`: exists.
- `package.json` declares TypeScript and Vite and invokes `tsc && vite build`; npm adds only the current package's `node_modules/.bin` to this script's executable path.
- The first junction attempt used `cmd.exe /c` under Git Bash. MSYS rewrote `/c`, opening an interactive prompt and creating nothing; `cmd.exe //c echo ...` executes correctly. Windows switches passed through Git Bash need the double-slash form here (`//c`, `//J`).

### Hypothesized root cause

The clean Git worktree does not carry the ignored `frontend/node_modules` dependency installation, so npm cannot resolve the locally declared `tsc` executable. · Confidence: high

## Phase 2 — Pattern

Git worktrees share tracked files but not ignored dependency directories. This is environment bootstrap, not a source/build regression. Installing dependencies separately in every short-lived worktree would duplicate the same tree and create avoidable package-manager churn.

## Phase 3 — Impact

Only frontend commands launched from this worktree are affected. The owner checkout has the required dependency tree. Backend tests already completed successfully, and no frontend source changed in TASK-229.

## Phase 4 — Solution

Create an ignored Windows directory junction from this worktree's `frontend/node_modules` to the owner checkout's existing `frontend/node_modules`, invoking `cmd.exe //c mklink //J` so Git Bash does not rewrite the Windows switches, then rerun the exact build. Also run the required build in the owner checkout for served-bundle verification. No package or production code change is needed.

## Resolution

Created the ignored junction with `cmd.exe //c mklink //J`; the exact worktree build then passed (`tsc && vite build`, 27 modules, 1.13s). No package or production code changed.
