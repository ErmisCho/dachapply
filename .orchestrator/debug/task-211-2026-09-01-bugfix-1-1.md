# Debug session: local CV candidate evidence disappears in detached runtime
Created: 2026-09-01T18:08:00Z
Session: task-211-2026-09-01-bugfix

## Phase 1 — Root Cause

### Error

Rendered Generate CV error (always after pressing Generate):

`Candidate evidence is empty: paste it into account settings, or fix the configured evidence file.`

The first read-only `manage.py shell` probe exited 1 with the intended database guard:

`django.core.exceptions.ImproperlyConfigured: DATABASE_URL came from a .env file, and that file can hold the production database. Refusing to start rather than risk a local manage.py command reaching it silently.`

The next command mistakenly used non-exporting Git-Bash syntax (`set DACHAPPLY_ALLOW_PROD_DB=1`) and repeated the same exit-1 guard. The deliberate read-only retry used exported `DACHAPPLY_ALLOW_PROD_DB=1` and succeeded.

### Reproduction

`cd C:/Users/Administrator/AppData/Local/dachapply/main-runtime/backend && DACHAPPLY_ALLOW_PROD_DB=1 ../.venv/Scripts/python.exe manage.py shell -c <read-only owner profile/settings/load_candidate_evidence probe>`

Environment: Windows, released detached runtime SHA `5b3a23486efd7386d7034e24b2d937b5e96e10f9`, DEBUG local runserver, repo-root `.env` hard-linked into the runtime. Frequency: always.

- `5611529 feat: complete remaining backlog workflows` — retained account evidence precedence and the host-file fallback; behavior is correct when the configured path exists.

### Hypothesized root cause

The detached local launcher moved `BASE_DIR.parent` away from the ignored owner evidence file without giving settings the original source-repository root. · Confidence: high

## Phase 2 — Pattern

This is a relocation/configuration-boundary bug: released tracked code moved to a disposable worktree while one intentional private input remained in the source checkout. Existing tests prove stored-evidence/file precedence and true-empty failure, but `test_local_runtime_launcher.py` checks only released SHA isolation and `.env` linking—not resolution of ignored private inputs. No other ignored DEBUG default uses `BASE_DIR.parent`; the tracked application-rules file survives the move.

## Phase 3 — Impact

Affected:

- `scripts/dachapply-local-runtime.cmd` — knows both source repo and detached runtime, so it is the one boundary that can identify the source root without guessing.
- `backend/config/settings.py` — computes the DEBUG fallback evidence path.
- `backend/jobradar/tests/test_local_runtime_launcher.py` — missing regression at this boundary.
- `backend/jobradar/services/cv_generator.py` callers `generate_cv_documents` and `revise_latest_cv_documents` — both fail before starting any model task.

Unaffected and intentionally preserved:

- pasted per-user `candidate_evidence` remains first priority;
- an explicit `CODEX_CANDIDATE_EVIDENCE_PATH` remains authoritative;
- non-owner capability gates and truly empty evidence continue to fail closed;
- deployed production has DEBUG false and no host-file fallback.

## Phase 4 — Solution

Have the local launcher export its already-validated `%REPO%` as `DACHAPPLY_SOURCE_REPO`. Use that source root only for the existing DEBUG default candidate-evidence path; explicit environment configuration and stored per-user evidence keep their current precedence. Add a focused runtime-boundary regression plus the existing synthetic evidence/empty/source-precedence tests.

## Resolution

`scripts/dachapply-local-runtime.cmd` now exports the already-validated source checkout as `DACHAPPLY_SOURCE_REPO`; `backend/config/settings.py` uses it only for the existing DEBUG fallback. `backend/jobradar/tests/test_local_runtime_launcher.py` verifies the detached boundary in a subprocess. Synthetic resolution produced a 42,287-character grounded context with evidence/rules labels; 1,046 backend tests, 206 frontend tests, build, Django checks, compileall, and migration check passed. Released-runtime/browser verification remains pending merge.
